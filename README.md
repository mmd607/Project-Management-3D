# 🧠🚀 Project Intelligence Manager

### 🌌 Your Personal Local-First Project Command Center

**Discover · Analyze · Understand · Visualize · Manage**



> **Turn your local development folder into an intelligent project universe.**

Project Intelligence Manager is a **local-first project intelligence and management workspace** designed for developers who work with multiple software projects.

It discovers projects from a selected local workspace, analyzes real filesystem evidence, builds transparent project profiles, calculates explainable health scores, and presents everything through an interactive visual environment.

**No cloud workspace required.
No repository upload by default.
No AI required for the core intelligence.**

# 🎯 Product Vision

Project Intelligence Manager is designed to become a **personal project manager for your local software ecosystem**.

Instead of treating projects as folders, it treats them as **intelligent entities**.

Instead of opening projects one by one, you explore them through one workspace.

Instead of guessing project quality, you inspect the evidence.

Instead of making AI responsible for everything, the system establishes a deterministic foundation first.

# 🗂️ Local Project Discovery

Select a local folder and Project Intelligence Manager searches for real software projects.

The discovery system looks for evidence such as:

* `.git`
* Project manifests
* Build configuration
* Package manager files
* Framework markers
* Recognized development structures

A directory is **not automatically considered a project just because it contains a README**.

The system tries to establish stronger evidence before creating a project entity.

---

# 🔍 Evidence-Based Scanner

Once projects are discovered, the scanner analyzes their filesystem structure.

It can detect:

### 💻 Technology

* Programming languages
* Frameworks
* Package managers
* Lockfiles
* Build systems

### 🧪 Engineering

* Test configuration
* Test directories
* CI/CD signals
* Deployment configuration
* Documentation

### 📦 Project Structure

* File count
* Project size
* Directory structure
* Configuration files

### 🌿 Git

* Git repository presence
* Current branch
* Repository information

The scanner is intentionally **non-executing**.

It does not run the project's code.


---

# 📊 Project Health Score

Every scanned project can receive an explainable **Project Health Score**.

The score is:

* deterministic
* weighted
* versioned
* evidence-based
* explainable

The system does not blindly treat missing information as failure.

Instead:

```text
Detected       → Evidence available
Not detected   → Evidence not found
N/A            → Not applicable / insufficient evidence
PARTIAL        → Scan was bounded or incomplete
```

This creates a more honest project evaluation model.

# 🤖 Optional AI Explanation

AI is an optional layer.

The core system does **not** require an AI provider.

By default:

```env
AI_PROVIDER=mock
```

This provides a deterministic offline experience.

When explicitly configured, Anthropic can provide the:

### `Explain this project`

capability.

```env
AI_PROVIDER=anthropic
ANTHROPIC_API_KEY=your_api_key
ANTHROPIC_MODEL=your_model
```

The AI receives a compact evidence-derived context rather than the entire repository.

### 🔐 Important

The system does **not** upload your entire project to an AI provider.

It does not automatically send:

* ❌ Entire repositories
* ❌ Raw project folders
* ❌ Arbitrary source code
* ❌ Files outside the selected workspace

The AI layer is intentionally separated from the deterministic intelligence engine.

# 🔐 Local-First by Design

Project Intelligence Manager is built around a simple privacy principle:

<div align="center">

## 🏠 Your Projects Stay Local

### By default.

</div>

The application processes project information locally.

The scanner:

* ❌ Does not execute project scripts
* ❌ Does not install dependencies
* ❌ Does not run builds
* ❌ Does not follow symbolic links
* ❌ Does not scan outside the selected workspace

---

# 🛡️ Filesystem Security

The scanner uses bounded traversal and explicit exclusion rules.

### Default exclusions

```text
.git/
node_modules/
venv/
build/
dist/
output/
cache/
.env
*.key
```

Large or problematic projects can be marked:

```text
PARTIAL
```

instead of blocking the complete workspace scan.

# 🚀 Getting Started

## 1. Clone

```bash
git clone https://github.com/mmd607/Project-Management-3D.git
cd Project-Management-3D
```

## 2. Install

```bash
npm install
```

## 3. Configure

```bash
cp .env.example apps/server/.env
```

Default configuration:

```env
AI_PROVIDER=mock
```

## 4. Initialize Database

```bash
npm run prisma:migrate -w apps/server
```

## 5. Start Backend

```bash
npm run dev:server
```

API:

```text
http://localhost:4310
```

Health:

```text
http://localhost:4310/api/health
```

Expected:

```json
{
  "ok": true
}
```

## 6. Start Frontend

Open another terminal:

```bash
npm run dev:web
```

Open:

```text
http://localhost:5173
```
